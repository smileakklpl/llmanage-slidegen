# PPT 圖表原生性與資料同步設計

> **版本**：v0.1
> **狀態**：POC 已驗證核心機制
> **對應規格書章節**：FR-2.2（圖表原生性）、FR-3（Excel 繪圖資料同步輸出）
> **相關程式**：`src/chart_builder.py`、`src/verify_chart_consistency.py`

---

## 1. 需求澄清

命題原文要求：

> 簡報中的圖表，**右鍵點擊「編輯資料」**，即可查看/修改原始資料表。

這**不是**「PPT 圖表連結到外部 Excel 檔案」，而是 PowerPoint 原生機制：圖表右鍵「編輯資料」開啟的，是**內嵌在 `.pptx` 檔案內部**的一份工作簿（embedded workbook），跟外部獨立的 `.xlsx` 檔案是兩個不同的東西。

因此正確的設計方向是：**生成 PPT 時，讓圖表的內嵌工作表與畫面顯示值同源自同一批解析後資料**，而非事後去「連結」一份外部 Excel。

---

## 2. 技術原理

### 2.1 PPT 圖表背後的三個部件

一張 PowerPoint 原生圖表，實際由三個部分組成：

| 部件 | 位置 | 作用 |
|------|------|------|
| Chart XML 快取值（`c:numCache` / `c:strCache`） | `.pptx` 內 `ppt/charts/chart1.xml` | PowerPoint **顯示**圖表時直接讀這裡，不會每次開檔都重新讀工作簿 |
| 內嵌工作簿（embedded workbook） | `.pptx` 內 `ppt/embeddings/Microsoft_Excel_Worksheet#.xlsx` | 使用者右鍵「編輯資料」時開啟、修改的來源 |
| 圖表物件本身（graphic frame） | slide XML 內 | 決定圖表在投影片上的位置、大小、類型 |

**風險點**：若這三者（尤其前兩者）數字不一致，就會出現「畫面上顯示 A 值，但右鍵編輯資料打開卻是 B 值」的問題——這正是附件三錯誤範例（P.5、P.7 座標軸與數值有誤）的技術根源之一。

### 2.2 解決方案：單一資料入口

python-pptx 的 `shapes.add_chart()` API，在**生成階段**會自動把同一批輸入資料，同時寫入 chart XML 快取與內嵌工作簿。只要全系統統一走這一個入口，兩者就保證一致，不需要額外的「同步」或「連結」邏輯。

```
ChartSpec（結構化資料）
        │
        ▼
   add_chart()  ←── 唯一入口，不手動操作底層 XML
        │
        ├──→ chart XML cache（畫面顯示值）
        └──→ 內嵌 workbook（右鍵「編輯資料」看到的值）

上述兩者由同一次 API 呼叫產生，天生一致。
```

## 3. 整體資料流

```
┌──────────────────────────────────────────┐
│  Excel 原始報表（附件四類，多工作表）        │
└────────────────────┬─────────────────────┘
                     ▼
┌──────────────────────────────────────────┐
│  解析引擎（pandas / openpyxl）              │
│  - 跨表關聯、欄位對應、加總計算              │
│  - YoY / MoM、市占率、有效卡率等指標計算     │
└────────────────────┬─────────────────────┘
                     ▼
┌──────────────────────────────────────────┐
│  LLM（洞察生成）                            │
│  - 輸入：解析後的結構化數字                  │
│  - 輸出：文案洞察（不負責計算數值，避免幻覺）  │
└────────────────────┬─────────────────────┘
                     ▼
┌──────────────────────────────────────────┐
│  ChartSpec / ScatterSpec（結構化中間資料）   │
│  = 系統的「唯一真相來源 (MetricStore)」      │
└────────────────────┬─────────────────────┘
                     ▼
┌──────────────────────────────────────────┐
│  chart_builder.py                          │
│  add_category_chart() / add_scatter_chart()│
└────────────────────┬─────────────────────┘
        ┌────────────┴────────────┐
        ▼                         ▼
  chart XML cache           內嵌 workbook
 （畫面顯示值）             （右鍵編輯資料值）
        │                         │
        └────────────┬────────────┘
                     ▼
          兩者透過同一入口生成，保證一致
                     │
                     ▼
        （另一條獨立路徑）FR-3 外部稽核用 .xlsx
        供使用者/主管獨立核對，不影響上述兩者
```

**重要原則**：LLM 只負責生成洞察文案，**不參與任何數值計算**。所有數字必須從解析引擎直接綁定到 `ChartSpec`，避免 LLM 幻覺造成數字與 Excel 不符（對應附件三揭露的問題）。

## 4. 三份資料副本與一致性要求

系統中同一組數字實際上會存在**三份副本**，設計上必須保證三者一致：

| 副本 | 位置 | 用途 | 產生方式 |
|------|------|------|----------|
| ① Chart XML 快取值 | `.pptx` 內 `chart#.xml` | PPT 畫面顯示 | `add_chart()` 自動產生 |
| ② 內嵌 workbook | `.pptx` 內 `embeddings/*.xlsx` | 右鍵「編輯資料」開啟 | `add_chart()` 自動產生，與①同源 |
| ③ FR-3 外部稽核 `.xlsx` | 獨立檔案，跟 PPT 一起寄送 | 使用者/主管獨立核對、稽核 | 由獨立的 writer 函式產生，餵入**相同**的 ChartSpec |

①②由同一次 `add_chart()` 呼叫產生，保證一致；③是另一條獨立輸出路徑，但因為輸入資料源頭相同（同一個 `ChartSpec`），數值仍然一致。三者不會互相「連動」——即使使用者事後在 PPT 裡雙擊改了內嵌工作表的值，也不會回寫影響外部稽核 `.xlsx`，這是預期行為（生成後的手動修改屬於使用者個人用途）。

## 5. 已驗證的 POC 成果

### 5.1 程式檔案

| 檔案 | 功能 |
|------|------|
| `src/chart_builder.py` | 定義 `ChartSpec` / `ScatterSpec` 資料結構，封裝 `add_category_chart()`、`add_scatter_chart()`，統一走 `add_chart()` 單一入口 |
| `src/verify_chart_consistency.py` | 自動化驗證腳本：套用 `ppt/template.pptx`，插入示範圖表後，比對「畫面顯示值」與「內嵌工作表值」是否一致 |

### 5.2 驗證邏輯

1. 從 `chart.plots[0].series[0].values` 讀出畫面顯示值（chart XML cache）
2. 從 `chart.part.chart_workbook.xlsx_part.blob` 讀出內嵌工作表的二進位內容，用 openpyxl 解析出實際數值
3. 比對兩者是否完全相等

### 5.3 驗證結果

```
[Slide 4] 圖表: 市場流通卡數（萬張）
  畫面顯示值 : [5865.5, 5874.8, ..., 6048.6]
  內嵌工作表值: [5865.5, 5874.8, ..., 6048.6]
  一致性: PASS

=== 最終結果: 全部一致 (PASS) ===
```

證實：套用 `template.pptx` 生成的圖表，右鍵「編輯資料」看到的內嵌工作表數字，與畫面顯示完全一致。

## 6. 圖表類型對應與已知限制

| 附件二要求的圖表 | python-pptx 對應方案 | 狀態 |
|---|---|---|
| 排名圖、成長率圖（長條/橫條） | `CategoryChartData` + `COLUMN_CLUSTERED` / `BAR_CLUSTERED` | 已實作並驗證 |
| 市占率圖（圓餅圖） | `CategoryChartData` + `PIE` | 同一入口，換 `chart_type` 即可，未實作 |
| 散點圖（規模 vs 成長） | `XyChartData` | 已實作 `add_scatter_chart()`，**資料點標籤（銀行名稱）尚未支援** |
| 熱力圖 | 無原生圖表類型 | 改用原生表格 + 儲存格底色模擬，**不屬於「圖表」，右鍵無「編輯資料」選項** |
| 雙軸圖（如流通卡數＋簽帳金額疊圖） | 無高階 API | 需手動操作底層 `chart._chartSpace` lxml，插入第二個 plot 並綁定第二軸 |

### 6.1 待解決事項

- **散點圖標籤**：附件三 P.10 每個資料點旁需顯示銀行名稱（中信、玉山...），python-pptx 無高階 API，需直接操作 `c:dLbls` XML 節點。
- **雙軸圖**：附件三 P.5 為流通卡數（長條）+ 簽帳金額（折線）雙軸疊圖，需要 low-level XML 插入，且需驗證手動插入不會破壞內嵌工作表的自動同步機制。
- **熱力圖是否符合「圖表可獨立修改」要求**：目前規劃走表格模擬，需與命題要求的「圖表」定義做確認。

## 7. 與模板（`ppt/template.pptx`）的整合方式

### 7.1 模板現況

- 5 頁骨架，6 種版面配置（標題頁 / 章節標題頁 / 標題及內容頁等）
- 目前**沒有任何圖表物件**，僅有標題、內容文字框（BODY placeholder）、頁碼 placeholder

### 7.2 生成邏輯

因為模板只是骨架，生成流程是「新增內容」而非「修改既有圖表」：

```
1. 選擇對應版面（如「1_標題及內容」）
2. 填入標題文字（Executive Summary、市場整體概況...）
3. 依該頁的圖表規劃，呼叫 add_category_chart() / add_scatter_chart()
   插入圖表到指定座標（left/top/width/height）
4. 若該頁需要表格，另外用 python-pptx 原生 table API 插入
```

POC 中已示範套用第 4 頁（`1_標題及內容` 版面）插入圖表並成功驗證。
