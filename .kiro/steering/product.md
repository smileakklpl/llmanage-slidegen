# 產品定位：智匯數據簡報神器

## 專案一句話
使用者以一段自然語言指令 + 一份多工作表 Excel 報表，系統在遠低於 15 分鐘內產出：

1. 一份套用台新新光金控模板、顧問風格、**每張圖表皆為 PPT 原生可編輯物件、數字 100% 正確且可追溯**的簡報（.pptx）
2. 一份與簡報圖表一一對應的原始資料 Excel（.xlsx）
3. 自動寄送至指定收件人（模擬信箱）

並具備：**模型可抽換**（雲端 ↔ 地端 LLM）與**資料更新可重生成**（Refresh）兩項架構特性。

## 競賽背景
- 2026 雲湧智生：臺灣生成式 AI 應用黑客松競賽
- 命題單位：台新新光金控
- 賽道：金融創新
- 團隊：LLManage

## 命題核心痛點（必須解決）
1. 簡報中的數字與圖表可能與實際 Excel 數字不符
2. 簡報圖表以幾何圖形堆疊而成，無法用 Excel 原生方式編輯
3. 簡報表格以幾何圖形和文字方塊堆疊，非真正表格
4. 完成後仍需人工透過 Email 寄送，流程缺乏自動化

## 範圍界定

### In Scope（必做）
- F1 數據智能解析引擎
- F2 PPT 模板綁定與原生圖表生成
- F3 Excel 繪圖資料同步輸出
- F4 自動寄送機制
- F5 一次性 prompt 端到端流程（Web UI 或 API 觸發）
- A1 模型抽換層（LLM abstraction）
- A2 Spec 驅動之重生成機制（資料更新 → 一鍵 Refresh）

### Stretch（加分項，行有餘力才做）
- S1 口述驅動模式（語音轉文字 → Agent 彙整跨表 → 產出）(+5%)
- S2 使用 Kiro 作為 AI 整合開發環境 (+5%)
- S3 多輪對話調整（例如「把 P.7 改成 Top 5」）
- S4 排程自動同步（Demo 以示意呈現）
- S5 模型分層呼叫（依頁面權重分層用模型，預設全案單一模型即可跑通）

### Out of Scope（明確不做）
- PPT 圖表以「外部連結 Excel」方式即時連動（路徑脆弱、與寄送情境衝突）
- 閉源 SaaS 簡報生成服務
- 真實 SMTP 對外寄信（以 MailHog 模擬信箱為準）

## 不可退讓的產品原則
1. **LLM 永遠不計算、不產生數字。** 所有數值必須來自確定性計算的 `engine`；LLM 負責的敘事若含數字，必以佔位符引用，由 renderer 代入實際值。這是避免附件三揭露的「數字與 Excel 不符」問題的根本設計。
2. **圖表必須是 PPT 原生 chart 物件**（內嵌 chart XML + embedded workbook），驗收標準是使用者在 PowerPoint 右鍵「編輯資料」可開啟資料表並修改。不接受以圖片或幾何圖形堆疊模擬圖表。
3. **表格必須是 PPT 原生 table 物件**，禁止文字方塊拼貼。
4. **防呆規則**：資料範圍外的指標不得產出（例如僅有單年資料時不得計算/呈現 YoY）。引擎需輸出「可計算指標清單」，敘事層只能引用清單內指標。
5. **可追溯性**：任一簡報數字必須可回溯至來源儲存格與計算公式。
